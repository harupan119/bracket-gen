# bracket-gen

サークルの団体戦・バレー大会などで使うトーナメント表を、条件を与えて自動生成します。
出力は Google スプレッドシートで、結果を入力すると勝者・次の対戦・勝ち上がりの色が自動で更新されます。

毎回ゼロから表を作り直すのをやめるための道具です。

## 対応している形式

| 形式 | チーム数 | 試合数 | 決まる順位 |
|---|---|---|---|
| シングルエリミネーション | 4〜20 | N（3位決定戦込み） | 1〜4位 |
| ダブルエリミネーション | 4〜20 | 2N-1（決勝リセット込み） | 1〜3位 |
| 完全順位決定トーナメント | **4 / 8 / 16 のみ** | N·log₂N / 2 | 全順位 |

チーム名は A から順に自動で割り振られます。実名は生成後、進行表の記入欄に書くと全タブに反映されます。

### 完全順位決定が 4 / 8 / 16 に限られる理由

この形式の価値は「全チームが同じ試合数を戦い、1位から最下位まで全部決まる」ことです。
これは N が 2 の冪のときにしか成立しません。10チームなどでシードを入れると試合数が
不均等になり、「なぜあのチームだけ2試合なのか」を当日に説明する羽目になります。
中途半端に動くより生成時点で弾く方が安全なので、エラーで拒否します。

なお **16チームだと32試合**になります。半日開催では収まらないことが多いので、
生成時に警告を出します。

## 使う（大会の運営をする人）

**テンプレート**: https://docs.google.com/spreadsheets/d/1cq1_MBFK37CHtbrB8eUmi24yvVfK911KC2gCA3ExZXY/edit

1. 上のテンプレートを開き、**ファイル → コピーを作成**
2. コピーを開き、上部メニューの **bracket-gen → 大会を作成**
3. 形式・チーム数・コート数を入力して「作成する」

インストールするものはありません。初回だけ Google の認可画面が出ます。

生成は、いま開いているコピーに直接書き込まれます。同じシートで作り直すと、
前回の内容と条件付き書式は消えてから作り直されます。

生成されるのは4つのタブです。

| タブ | 役割 |
|---|---|
| トーナメント表 | ブラケット図と最終順位。勝ち上がった経路が赤くなる |
| 進行表 | チーム名の記入欄と、枠ごとの進行一覧 |
| スマホ用 | **結果を入力する唯一の場所。** 当日はここだけ見る |
| 試合管理 | 非表示。依存関係と勝敗判定の数式 |

結果は **スマホ用タブの黄色いセル**だけに入れます。他のタブは自動で追随します。
Google スプレッドシートの標準機能では2箇所の入力欄を双方向に同期できないため、
入力口は1つに固定しています。

### 時刻は出しません

コート数は「どの試合を同時に流すか」の判定にだけ使い、開始時刻は出しません。
「枠1が終わったら枠2へ」という進め方を想定しています。
昼休みのような不規則な休憩は、生成後に手で行を挿入してください。

### 連戦は避けません

初版では、同じチームが連続で試合に入ることを避ける処理は入れていません
（同じ枠に同じチームが2回入ることはありません。それは物理的に不可能なので防いでいます）。
試合順を決める部分は差し替えできるようにしてあるので、必要になったら
`core/schedule.js` に別のストラテジを足してください。

## 継承についての注意

**テンプレートのスプレッドシートは harupan119 の個人 Google ドライブにあります。**
（https://docs.google.com/spreadsheets/d/1cq1_MBFK37CHtbrB8eUmi24yvVfK911KC2gCA3ExZXY/edit）

このアカウントが整理・削除されると、後から入った人はテンプレートにアクセスできなくなります。
引き継ぐときは、次のどちらかを済ませてください。

- サークル用の Google アカウントを作り、テンプレートの所有者をそこへ移す
- 自分のドライブにコピーを作り、そのリンクを配り直す

コード自体はこのリポジトリにあるので、テンプレートが失われても作り直せます。
ただし手間がかかるので、失う前に移しておく方が楽です。

## 開発

```bash
npm test        # 構造・レイアウト・数式・ペイロードの検証
npm run build   # core/ を Apps Script 用の1ファイルへ束ねる

# レイアウトをブラウザで確認する（Sheets へ往復しない）
node tools/preview.mjs '{"format":"double-elimination","teams":10,"courts":4}' > preview.html
```

`tools/preview.mjs` は生成ペイロードが持つ書式をそのままHTMLへ描き出します。
罫線や地色の崩れは実際に見ないと分からないので、Sheets へ書き込む前の確認に使います。
条件付き書式は結果データに依存するため描きません（静的な意匠の確認用）。

Apps Script の V8 ランタイムは `import` / `export` を解釈しません。
`core/` は素の ES モジュールとして書き、esbuild で `apps-script/core.bundle.gs` へ
束ねてから配置します。**バンドル結果はリポジトリにコミットしてあります。**
後から入った人がビルド環境を用意しなくても、スプレッドシートをコピーするだけで
動く状態を保存しておくためです。

### 勝ち上がりの見せ方

Google スプレッドシートの条件付き書式は**罫線に触れません**。そのため枝線そのものの色は変えられません。
代わりに、ブラケットの連結列（幅の狭い空セル）を勝者の色で塗ることで、
マーカーでなぞったように経路を見せています。

### 検証の考え方

形式ごとに、その定義そのものを不変量としてテストしています。

- **完全順位決定**: 全チームの試合数が等しく、順位が重複も欠けもなく決まる（8チームは全4096通りを総当たり）
- **ダブルエリミ**: 優勝チーム以外は必ずちょうど2敗して終わる
- **シングルエリミ**: 優勝は無敗、それ以外はちょうど1敗

レイアウトは、同一セルへの二重書き込みと結合セルの重なりを機械で検出します。
目視で崩れを探すのは最後の1回だけで済ませるためです。

### 実際に動かさないと見つからない不具合

ローカルのテストでは原理的に検出できない種類の問題が3つありました。同じ轍を踏まないよう記録します。

1. **結果セルには `numberFormat: TEXT` が必須。**
   `2-1` や `1-2` を書くと Google スプレッドシートが日付として解釈し、日付シリアル値になります。
   勝敗判定の文字列比較が黙って外れますが、`3-0` / `0-3` は不正な日付なので文字列のまま残るため、
   一部の試合だけ勝者が反転するというまだらな症状になります。

2. **条件付き書式の数式は他シートを参照できません。**
   API が `Invalid ConditionValue.userEnteredValue` で拒否します。
   `INDIRECT` で回避できますが再計算が遅れて色が残るため、
   対象シート内に隠し補助列（H列＝勝者 / I列＝敗者）を置いて、そこを参照しています。

3. **条件付きの試合（決勝リセット）は、左右の割り当て規約をモデルと揃える必要があります。**
   元の試合の当初の左右を出すと、同じ `1-2` が逆の勝者を指します。

詳細は `findings.md` に残しています。
